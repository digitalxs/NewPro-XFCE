# NewPro-XFCE v2.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship PRO-dark-XFCE-4.20 v2.3: parse-clean CSS, one radius scale, rounded menus and xfwm4 corners, Thunar-style panel, distro-logo script, KvArc-based Kvantum theme, recommended-setup docs.

**Architecture:** Theme files stay where they are. Generated assets (xfwm4 corners, Kvantum theme) are produced by committed, re-runnable scripts in `tools/`. A stdlib-`unittest` suite in `tests/` checks the theme files and scripts; GTK parsing is checked through PyGObject in a separate process per GTK version.

**Tech Stack:** GTK3/GTK4 CSS, XPM, Kvantum (SVG + INI), Python 3 stdlib (+ PyGObject for GTK parse tests), POSIX sh, xfconf-query.

**Spec:** `docs/superpowers/specs/2026-10-17-v2.3-design.md`

## Global Constraints

- Target: XFCE 4.20.x, Debian 13, GTK 3.24 and GTK ≥ 4.16 (Debian ships 4.18).
- Radius scale: small `6px`, medium `8px`, window `10px`; `0` and pill/circle values unchanged.
- Theme CSS never sets `font-family` or `font` (except existing `font: initial` resets).
- No proprietary files in the repo (no Segoe UI).
- GTK2 (`gtk-2.0/`) untouched.
- `Kvantum/` is GPL-3.0-or-later (from KvArc); rest of repo GPL-2.0-or-later.
- Colours: window `#dde2e7`, view `#ffffff`, text `#202020`, accent `#5597e1`, slate `#646772`, menubar/panel face `#b5b8be`→`#b6b9c0`, edge `#7e8185`.
- Tools are stdlib-only Python 3 or POSIX sh. Nothing is pushed, merged or tagged without the author's explicit OK.
- Commits: author is the repo-local identity; every message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **No compositor** → rounded menus/panel/corners must degrade to square, never to black or garbage. Covered by Task 8 manual check with picom stopped and xfwm4 compositing off.
2. **Distro with no logo in the icon theme** (e.g. `ID=void`, no `ID_LIKE` match) → script changes nothing and exits 0 with a message. Test in Task 5.
3. **`os-release` quoting variants** (`ID="ubuntu"`, `ID=arch`, `ID_LIKE="rhel centos fedora"`) → parsed identically. Test in Task 5.
4. **Panel with no Applications/Whisker plugin, or several of them** → zero or all updated, no error. Test in Task 5.
5. **Linked button groups** (path bar, spin buttons, combo entries) keep square inner edges after the radius rewrite. Test in Task 1 (no partial radius may round an inner edge: patterns like `6px 0 0 6px` preserved).

### Task 3: xfwm4 rounded corners generator

**Files:**
- Create: `tools/make-corners.py`, `tests/test_corners.py`
- Modify (generated): `PRO-dark-XFCE-4.20/xfwm4/top-{left,right}-{active,inactive,active-shaded}.xpm`; `xfwm4/themerc` only if `button_offset` needs it.

**Interfaces:**
- Produces: CLI `python3 tools/make-corners.py [--radius 10] [--xfwm-dir PRO-dark-XFCE-4.20/xfwm4]`; module functions `read_xpm(path) -> tuple[int, int, list[list[str | None]]]` (width, height, rows of `#rrggbb` or `None`) and `write_xpm(path, var_name, pixels) -> None`.
- Source mapping: `top-left-active`/`top-right-active` ← `title-1-active.xpm`; `*-inactive` ← `title-1-inactive.xpm`; `*-active-shaded` ← `title-1-active-shaded.xpm`. Row colour = pixel at column 0 of that row in the source.

- [ ] **Step 1:** Write `tests/test_corners.py` (runs the generator into a temp copy of `xfwm4/`):
  - `test_dimensions`: every generated XPM is 10 wide × 26 high.
  - `test_outer_pixel_transparent`: top-left file pixel (0,0) is `None`; top-right pixel (9,0) is `None`.
  - `test_rows_below_radius_opaque`: rows 10–25 contain no `None`.
  - `test_body_matches_title`: for rows 10–25, every pixel equals the source title row colour.
  - `test_mirror`: right corner == left corner mirrored horizontally.
  - `test_idempotent`: running twice produces byte-identical files.
  - `test_roundtrip`: `read_xpm(write_xpm(x)) == x`.
- [ ] **Step 2:** Run. Expected: FAIL (`tools/make-corners.py` missing).
- [ ] **Step 3:** Implement. Coverage per pixel by 4×4 supersampling against a circle of radius R centred at (R, R) (left corner): coverage `< 0.5` → `None`; `1.0` → row colour; otherwise mix row colour with `#7e8185` by `(1 − coverage)`. XPM writer: palette characters from a fixed printable alphabet, sorted colours for determinism, `None` → `" "`.
- [ ] **Step 4:** Run tests. Expected: PASS. Then run the tool on the real `xfwm4/` dir.
- [ ] **Step 5:** Reload with `xfwm4 --replace &` (theme selected), screenshot a window's top corners at 600% (`import -window root -crop …`), confirm no step between corner and title and buttons not clipped; adjust `button_offset` if they are.
