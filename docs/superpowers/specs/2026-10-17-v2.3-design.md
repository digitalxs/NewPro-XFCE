# NewPro-XFCE v2.3 — Design

Date: 2026-10-17
Base: `master` @ `aeb1f58` (tag `NewPro-XFCE-v2.2`)
Branch: `v2.3`

## Goal

Modernise PRO-dark-XFCE-4.20 without losing its identity: one consistent
rounded-corner scale, rounded window corners, a panel that matches Thunar's
menu bar, automatic distro logo, a matching Kvantum theme for Qt apps, and a
documented "recommended setup". The look was prototyped live on the author's
Debian 13 / XFCE 4.20 workstation (user overrides in `~/.config/gtk-3.0/gtk.css`)
and v2.3 moves it into the theme.

## Non-goals

- No font is set by the theme. Fonts stay a user choice in Settings → Appearance.
- No proprietary assets in the repo (Segoe UI is recommended, never shipped).
- GTK2 (`gtk-2.0/main.rc`) is not restyled.
- No install script (out of scope for this release).

## 1. Radius scale (GTK3 + GTK4)

| Token | Value | Applies to |
|---|---|---|
| small | 6px | buttons, entries, spin buttons, combo boxes, tooltips, focus rings, progress/scale troughs, selectable list rows |
| medium | 8px | menus, popovers, GTK-drawn panel popups, notifications, cards/frames |
| window | 10px | headerbar / CSD window top corners |
| — | `0` / `50%` unchanged | flush or joined edges (inner sides of linked buttons, notebook tab bars, toolbars, panel buttons) and circular controls |

- `gtk-3.0/gtk.css` (241 radius rules) and `gtk-3.0/gtk-dark.css` (100) are
  rewritten per selector role using the table. Partial radii keep their shape
  (`5px 0 0 5px` → `6px 0 0 6px`). GTK3 has no CSS variables, so a header
  comment in each file documents the scale.
- `gtk-4.0/_colors.css` gains `--radius-small: 6px; --radius-medium: 8px;
  --radius-window: 10px;` (GTK ≥ 4.16 supports custom properties; Debian 13
  ships 4.18). The 14 radius rules in `gtk-4.0/gtk.css` use `var(--radius-*)`.

## 2. xfwm4 rounded corners

- New `tools/make-corners.py` (Python 3, stdlib only) regenerates the six
  `xfwm4/top-{left,right}-{active,inactive,active-shaded}.xpm` at 10px width
  and the existing 26px height.
- For every row it takes the colour from the matching `title-1-*.xpm` row and
  draws an anti-aliased quarter circle of radius 10; pixels outside the arc
  are `None`, edge pixels are blended toward the colour of the row's outer
  edge (XPM has no partial alpha).
- `themerc` unchanged except `button_offset`, re-checked against the wider
  corner.
- The script is committed so corners can be regenerated when colours or the
  radius change.

## 3. Panel, distro logo, metadata, docs

### Panel = Thunar menu bar

Replace the `.xfce4-panel.background` block (~line 13374 of `gtk-3.0/gtk.css`)
with the rules validated on the workstation:

- face `linear-gradient(to top, #7e8185 1px, #b5b8be 1px, #b6b9c0)`,
  fallback `background-color: #b6b9bf`
- text `#202020`, `font-weight: normal`, no text/icon shadow
- buttons flat (transparent, no border, radius 0)
- `:hover`, `:active`, `:checked` → `#646772` background, white label
- `border-radius: 0 0 6px 6px` (needs a compositor; documented)

Panels whose Background style is not "None (use system style)" override
this — documented in README.

### Distro logo

New `tools/set-distro-logo.sh` (POSIX sh, needs `xfconf-query`):

1. Read `/etc/os-release` (`LOGO`, `ID`, `ID_LIKE`).
2. Candidates, in order: `$LOGO`, `distributor-logo-$ID`, `$ID-logo`, then
   `distributor-logo-$x` / `$x-logo` for each `x` in `ID_LIKE`.
3. Pick the first candidate that exists as a file in the active icon theme
   or `hicolor`, searched with `find` under `~/.local/share/icons/<theme>`,
   `/usr/share/icons/<theme>` and `/usr/share/pixmaps`.
4. Set `button-icon` on every `applicationsmenu` and `whiskermenu` plugin
   found in the `xfce4-panel` channel. No match → change nothing, print why.
5. `--dry-run` prints the chosen icon and the plugins it would change.

### Metadata

`index.theme`: `IconTheme=Papirus` (dark glyphs suit the light panel),
`CursorTheme=Bibata-Modern-Ice`.

### Extras

`extras/picom.conf`: glx backend, vsync, `corner-radius = 10`, soft shadows,
fades; panel/dock/desktop excluded from rounding and shadows.

## 4. Kvantum theme

- Location: `Kvantum/PRO-XFCE/PRO-XFCE.kvconfig` + `PRO-XFCE.svg`; installs to
  `~/.config/Kvantum/PRO-XFCE/`.
- Base: **KvArc** from `qt-style-kvantum-themes` (GPL-3.0-or-later).
  `Kvantum/` carries a `COPYING` (GPL-3) and credits KvArc / Tsu Jan.
  Compatible with the repo's GPL-2.0-or-later; README states the Kvantum
  folder is GPL-3.0-or-later.
- Palette: window `#dde2e7`, base/view `#ffffff`, alt base `#f5f7f9`,
  text `#202020`, accent/highlight `#5597e1` (focus, checks, progress),
  selected rows / menu hover `#646772` + white text, toolbar & menubar the
  Thunar grey gradient (`#b5b8be` → `#b6b9c0`, edge `#7e8185`).
- Radii follow §1 (6px widgets, 8px menus/popups).
- `.kvconfig`: no font overrides, no translucent windows, menus opaque with
  8px corners, `respect_DE=true`.
- Apply on the workstation via `kvantummanager --set PRO-XFCE` and
  `QT_STYLE_OVERRIDE=kvantum` (Qt5/Qt6) — documented, not forced.
